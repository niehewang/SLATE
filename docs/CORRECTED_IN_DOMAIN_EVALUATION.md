# Corrected in-domain matched evaluation

The current in-domain evidence supersedes the earlier descendant-informed query-selection protocol. Query informativeness is computed only from enrolled-source and alternative-source reference responses.

## Matched-effectiveness result

Under matched q=64 sessions on a fresh WildChat pool, complete SLATE produced a large history-aware channel-cover effect at L=4/L=8 relative to Unwrapped, while honest and bounded-attack correct-source verification utility was not preserved. The result therefore establishes a cover / fail-safe boundary rather than a universal end-to-end protection advantage.

## Operating-region result

Across the frozen five-point lambda grid, the L4 matched-cover criterion passes at every point, while the original honest-utility criterion and bounded-attack utility criterion do not. Full is clearly separated from Marginal-Cover on L4 cover, whereas Schedule-Only is competitive with Full under the predeclared +0.20 method-specificity scale.

AIR-matched random-routing controls are reported separately so selective routing can be compared with equal-volume random diversion without changing realized AIR.

The machine-readable aggregate evidence is in `results/corrected_in_domain/`. Raw conversational data, raw response banks, exact conversation IDs, long logs, and server return archives are intentionally not redistributed.
